# 测试设计能力验收清单

用于验证“测试设计”智能体及 `functional-test-design`、`test-asset-format` 共享能力是否真正执行风险驱动、可追踪的测试设计。该清单只评估能力,不保存任何项目业务资产。

## 一票否决项

出现任意一项,本次能力验收不通过:

- 用例未关联任何验收条件、风险或质量规则(`traceability` 为空)。
- 验收条件覆盖矩阵存在“未覆盖”且无暂缓说明和关联问题 ID。
- 暂缓项未关联未关闭问题 ID(`question_ref` 不符合 `Q-NNN`)。
- 评审结论为阻塞或存在未关闭 P0 问题时,仍创建了测试设计文件。
- 为未关闭的待确认问题批量创建了精确预期用例(而非暂缓项)。
- 覆盖矩阵状态使用了 `test-asset-format §覆盖矩阵状态` 之外的枚举值。
- 用例预期结果包含“正常、合理、友好”等不可判定词,且无量化定义。
- 提前创建了接口测试、执行结果、缺陷或报告等下一阶段文件。

## 场景一:评审通过的主流程覆盖

### 输入

评审结论为通过,主流程验收条件 `AC-NNN` 明确,无未关闭 P0 问题。

### 预期

- 读取评审文件的当前结论,确认无未关闭 P0 问题后开始设计。
- 每条验收条件至少有一条用例覆盖,覆盖矩阵状态为“已覆盖”。
- 主流程用例优先级为 P0,且关联对应 `AC-NNN`。
- 测试设计文件保存到 `04-test-design/`,不创建下一阶段文件。

## 场景二:有条件通过且存在未关闭 P1/P2 问题

### 输入

评审结论为“有条件通过”,无未关闭 P0 问题,但存在未关闭 P1/P2 问题。

### 预期

- 开始测试设计,不因 P1/P2 未关闭而停止。
- 引用未关闭问题的用例,预期结果写“按问题 ID 确认后判定”,不制造精确预期。
- 未关闭问题记录为暂缓项,关联 `Q-NNN`。

## 场景三:边界与异常覆盖

### 输入

需求包含数值边界、状态迁移、多条件组合。

### 预期

- 边界值用例覆盖有效和无效等价类边界。
- 状态迁移用例覆盖合法迁移和非法迁移。
- 判定表用例覆盖条件组合,不遗漏冲突列。
- 异常和恢复路径有对应用例,且关联风险 `R-NNN`。

## 场景四:平台专项覆盖

### 输入

`project.yaml.platforms` 包含 `web` 或 `mobile-app`。

### 预期

- 加载对应平台 skill,补充平台专项测试点。
- 平台专项用例不重复通用业务用例。
- 跨端差异用例标注“确认设计”或“潜在风险”。

## 场景五:覆盖矩阵完整性

### 输入

已完成测试点、用例和暂缓项编写。

### 预期

- 验收条件覆盖矩阵列出全部 `AC-NNN`,无遗漏。
- 风险覆盖矩阵列出全部 `R-NNN`,高风险至少有正常或异常控制用例。
- “部分覆盖”和“待确认后覆盖”附带说明;“未覆盖”必须关联暂缓项。
- 暂缓项与未关闭问题一一对应,无孤立暂缓项。

## 结构完整性

- [ ] 文档说明引用原始需求和评审文件路径
- [ ] 测试范围、排除项、假设和策略完整
- [ ] 测试数据有稳定 `D-NNN` 编号
- [ ] 测试点分层组织,不混杂用例步骤
- [ ] 用例字段符合 `test-asset-format §用例字段`
- [ ] 用例 ID 符合 `<FEATURE>-<TYPE>-NNN` 格式
- [ ] 覆盖矩阵状态符合 `test-asset-format §覆盖矩阵状态` 枚举
- [ ] 暂缓项均关联 `Q-NNN` 且说明影响范围
- [ ] 评审存在未关闭 P0 问题时未创建测试设计文件
- [ ] 未提前创建接口测试、执行结果或报告文件

## 通过标准

五个场景全部满足预期、结构完整性全部勾选,且不存在一票否决项,能力验收才通过。
