# 架构约定

## 分层

| 层级 | 目录 | 责任 |
|---|---|---|
| 编排层 | `.github/agents/` | 选择共享能力、读取项目上下文、生成资产 |
| 能力层 | `.github/skills/` | 跨项目可复用的方法、流程和检查规则 |
| 配置层 | `config/`、`projects/*/project.yaml` | 全局默认与项目覆盖 |
| 结构层 | `schemas/`、`templates/` | 数据约束和空白资产骨架 |
| 工具层 | `tools/` | GitHub、Apifox 等外部系统适配 |
| 项目层 | `projects/` | 项目知识、原始需求和生成资产 |
| 评估层 | `evaluations/` | 验证智能体和共享能力是否遵守质量约束 |

## 依赖方向

智能体可以读取共享能力、配置、模板、结构约束和项目资产。共享能力、模板、结构约束与工具不得依赖具体项目；项目可以引用可复用能力，但不能修改其语义。

## 配置优先级

```text
功能配置（可选） > 项目配置 > config/defaults.yaml
```

只在需求确有特殊策略时创建功能配置，避免重复项目级设置。

## 项目资产生命周期

```text
01-source/ -> 02-analysis/ -> 03-frozen-requirement.md -> 04-test-design/
```

原始输入保持不变。评审结果必须区分事实、问题、风险和假设；未确认内容不得作为缺陷判定依据。是否从评审进入测试设计由人工决定，AI 不自动串联阶段。

需求评审默认使用一个 `02-analysis/requirement-review.md`：顶部维护当前有效结论，底部追加各轮摘要和复评增量。只有文件明显过长、需要权限隔离或用户明确要求时才拆分轮次文件。评审通过且无未关闭 P0 后生成 `03-frozen-requirement.md` 作为最终需求规格。
